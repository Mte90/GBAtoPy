## Test Scripts

### `run_tests.py` — Unified 3-Level Test Runner

**Purpose:** Single command for full verification at three levels — syntax, execution, and visual comparison.

**Test Levels:**

| Level | What it verifies | What it does NOT verify |
|-------|------------------|--------------------------|
| 1 (syntax) | Transpile ROM + `py_compile` passes | Graphics, audio, execution behavior |
| 2 (execution) | Generated script runs headless without crash | Correct graphics/audio output |
| 3 (visual) | Screenshot matches mGBA golden (pixel diff < threshold) | Gameplay logic, audio accuracy |

**Usage:**
```bash
# Level 1 only (default — same scope as run-all-tests.sh)
python3 scripts/run_tests.py

# Levels 1+2 (syntax + execution)
python3 scripts/run_tests.py --level 2

# Levels 1+2+3 (full visual verification)
python3 scripts/run_tests.py --level 3

# Single ROM
python3 scripts/run_tests.py --rom hello --level 3

# Filter by name
python3 scripts/run_tests.py --filter mode3 --level 2

# Parallel workers (default: 4)
python3 scripts/run_tests.py --workers 8

# Custom frame count for execution
python3 scripts/run_tests.py --level 2 --frame 120

# Save JSON report to specific path
python3 scripts/run_tests.py --level 3 --json test-reports/report.json

# Skip building the transpiler (use existing binary)
python3 scripts/run_tests.py --no-build
```

**Output:** Per-ROM per-level status in console + timestamped JSON report in `test-reports/`.

**Note:** Level 3 requires golden screenshots to exist in `scripts/screenshot/golden/`. Use `generate_goldens.py` to create them. ROMs without goldens are reported as `no_golden` (not a failure).

### `run-all-tests.sh` — Smoke Test Suite

**Purpose:** Verify that all test ROMs transpile to syntactically valid Python. Equivalent to `run_tests.py --level 1`.

**What it DOES:**
- ✅ Transpile each ROM using the Rust CLI
- ✅ Run `py_compile` on generated Python files
- ✅ Report PASS/FAIL for each ROM
- ✅ Generate JUnit XML report (optional: `--junit`)

**What it does NOT do:**
- ❌ Execute the generated Python scripts
- ❌ Verify graphics rendering
- ❌ Verify audio playback
- ❌ Compare with golden screenshots

**Usage:**
```bash
# Run all ROMs (may take 10-15 minutes)
./scripts/run-all-tests.sh

# Quick mode (skip ROMs >1MB)
./scripts/run-all-tests.sh --quick

# Generate JUnit report
./scripts/run-all-tests.sh --junit

# Filter by ROM name
./scripts/run-all-tests.sh --filter mode3
```

**Output:** Results in `test-reports/test-results.txt` and optionally `test-reports/results-junit.xml`

```bash

## Audio Capture

### `audio/capture_golden.sh` — Golden Audio Capture

**Purpose:** Capture golden audio from a GBA ROM using mGBA's SDL disk audio driver. Outputs raw PCM that can be converted to WAV.

**Usage:**
```bash
# Default: capture 60 frames
./scripts/audio/capture_golden.sh --rom test_roms/roms/stripes.gba

# Custom frame count
./scripts/audio/capture_golden.sh --rom test_roms/roms/stripes.gba --frame 120

# Custom output file
./scripts/audio/capture_golden.sh --rom test_roms/roms/stripes.gba --output /tmp/stripes_audio.raw
```

**Environment:** Automatically sets up mGBA library paths and SDL audio driver. No manual configuration needed.

---

### `audio/capture_transpiled.py` — Transpiled Audio Capture

**Purpose:** Capture audio from a transpiled GBA ROM Python file and write to a 16-bit stereo WAV file at 44100Hz.

**What it does:**
- ✅ Import a transpiled ROM module (standalone Python file)
- ✅ Access the global `apu` instance from the module
- ✅ Call `apu._generate_samples()` in a loop for N frames
- ✅ Convert 8-bit unsigned samples to 16-bit signed
- ✅ Write to WAV file with proper RIFF header

**Requirements:**
- The transpiled ROM must expose a global `apu` instance from `gba_runtime.apu`
- The APU must have a `_generate_samples(count)` method that returns raw audio bytes

**Usage:**
```bash
# Capture 300 frames (~5 seconds) - default
python3 scripts/audio/capture_transpiled.py /tmp/stripes.py /tmp/stripes_audio.wav

# Custom frame count (e.g., 60 frames = ~1 second)
python3 scripts/audio/capture_transpiled.py /tmp/hello.py /tmp/hello.wav --frames 60

# Longer capture (600 frames = ~10 seconds)
python3 scripts/audio/capture_transpiled.py /tmp/mode3.py /tmp/mode3.wav --frames 600
```

**Output:** 16-bit stereo WAV file at 44100Hz

**Example workflow:**
```bash
# 1. Transpile ROM
cargo run -p gbatopy-cli -- pipeline --rom test_roms/roms/stripes.gba --output /tmp/stripes.py

# 2. Capture golden audio from mGBA
./scripts/audio/capture_golden.sh --rom test_roms/roms/stripes.gba --frame 300 --output /tmp/stripes_golden.wav

# 3. Capture audio from transpiled ROM
python3 scripts/audio/capture_transpiled.py /tmp/stripes.py /tmp/stripes_transpiled.wav --frames 300

# 4. Compare audio
python3 scripts/verify/compare_audio.py /tmp/stripes_golden.wav /tmp/stripes_transpiled.wav
```

### `compare_screenshots.py` — Golden Screenshot Comparison

**Purpose:** Compare mGBA golden screenshot with transpiled ROM screenshot pixel-by-pixel. Detects false-positive matches where both images are empty/black.

**What it does:**
- ✅ Load two PNG images (golden vs transpiled)
- ✅ Resize golden if needed (`--resize-golden`)
- ✅ Calculate pixel-by-pixel difference
- ✅ Report difference percentage and max pixel difference
- ✅ Detect both-black/both-empty images → reports INCONCLUSIVE (not PASS)
- ✅ Generate visual diff image highlighting differences (optional: `--output-diff`)
- ✅ JSON report output (optional: `--output-json`)

**Usage:**
```bash
# Compare single pair (positional args)
python3 scripts/verify/compare_screenshots.py -s /tmp/golden.png /tmp/transpiled.png

# With custom threshold (default: 30)
python3 scripts/verify/compare_screenshots.py -s golden.png transpiled.png --threshold 20

# Batch compare multiple ROMs
python3 scripts/verify/compare_screenshots.py -b stripes hello mode3 \
  --golden-dir scripts/screenshot/golden/ \
  --transpiled-dir /tmp/transpiled/

# With visual diff output and JSON report
python3 scripts/verify/compare_screenshots.py -s golden.png transpiled.png \
  --output-diff /tmp/diffs/ \
  --output-json /tmp/report.json
```

**Statuses:**
- `PASS` — pixel difference below threshold AND both images have content
- `FAIL` — pixel difference at or above threshold
- `INCONCLUSIVE` — both images are empty/black (cannot determine correctness)

### `compare_audio.py` — Golden Audio Comparison

**Purpose:** Compare mGBA golden audio with transpiled ROM audio using time-domain and optional FFT-based spectral analysis.

**What it does:**
- ✅ Load both 8-bit and 16-bit WAV files (auto-detects format)
- ✅ Normalize samples to float64 in range [-1.0, 1.0]
- ✅ Compute time-domain metrics: mean diff, RMS diff, correlation
- ✅ Detect silent files (both below noise floor) → reports SKIP (not PASS)
- ✅ Optional FFT-based spectral comparison (`--spectral` flag)
- ✅ Report content percentage for both files

**Format Support:**
- 8-bit unsigned WAV (converts from [0, 255] to [-1.0, 1.0])
- 16-bit signed WAV (converts from [-32768, 32767] to [-1.0, 1.0])
- Mono and stereo files (stereo mixed to mono for comparison)

**Usage:**
```bash
# Basic comparison (time-domain only)
python3 scripts/verify/compare_audio.py golden.wav transpiled.wav

# With FFT-based spectral comparison
python3 scripts/verify/compare_audio.py golden.wav transpiled.wav --spectral

# Custom threshold (default: 30.0%)
python3 scripts/verify/compare_audio.py golden.wav transpiled.wav --threshold 20.0

# Include frame count in report
python3 scripts/verify/compare_audio.py golden.wav transpiled.wav --frame 300
```

**Exit codes:**
- `0` — PASS or SKIP (both silent)
- `1` — FAIL or error

**Statuses:**
- `PASS` — difference below threshold AND both files have content
- `FAIL` — difference at or above threshold
- `SKIP` — both files silent (below 0.1% content threshold)

**Metrics reported:**
- **Time-domain:** mean_diff, rms_diff, correlation, diff_percentage
- **Content:** golden_content%, transpiled_content% (percentage of samples above noise floor)
- **Spectral (with --spectral):** spectral_correlation, spectral_diff, num_fft_bins

**Example workflow:**
```bash
# Capture golden audio
./scripts/audio/capture_golden.sh --rom test_roms/roms/stripes.gba --frame 300 --output /tmp/stripes_golden.wav

# Capture transpiled audio
python3 scripts/audio/capture_transpiled.py /tmp/stripes.py /tmp/stripes_transpiled.wav --frames 300

# Compare with time-domain only
python3 scripts/verify/compare_audio.py /tmp/stripes_golden.wav /tmp/stripes_transpiled.wav

# Compare with spectral analysis
python3 scripts/verify/compare_audio.py /tmp/stripes_golden.wav /tmp/stripes_transpiled.wav --spectral
```

## Screenshot Capture

### `screenshot/screenshot.lua` — Parameterized mGBA Screenshot Capture

**Purpose:** Lua script for mGBA that captures a screenshot at a specified frame. Reads configuration from environment variables, making it reusable for any ROM.

**Environment variables:**
- `GBATOPY_SCREENSHOT_PATH` — output path (without `.png` extension)
- `GBATOPY_TARGET_FRAME` — frame number to capture (default: 60)

**Usage:**
```bash
GBATOPY_SCREENSHOT_PATH=/tmp/golden_hello \
GBATOPY_TARGET_FRAME=60 \
./mgba/build/sdl/mgba -S scripts/screenshot/screenshot.lua test_roms/roms/hello.gba
```

**Note:** `generate_goldens.py` uses this script automatically. You rarely need to call it directly.

---

### `trace/trace.lua` — Execution Trace Script

**Purpose:** Lua script for mGBA that traces execution at frame boundaries. Outputs JSON trace for analysis.

**Environment variables:**
- `GBATOPY_TRACE_PATH` — output JSON path without extension (default: `/tmp/trace`)
- `GBATOPY_TRACE_MAX_FRAMES` — max frames to trace before stopping (default: 1000)

**Output format:**
```json
{
  "entries": [{ "frame": 1, "note": "execution" }, ...],
  "metadata": { "frame_count": 500 }
}
```

**Usage:**
```bash
GBATOPY_TRACE_PATH=/tmp/trace_hello \
GBATOPY_TRACE_MAX_FRAMES=500 \
./mgba/build/sdl/mgba -S scripts/trace/trace.lua test_roms/roms/hello.gba
```

**Limitation:** This version of mGBA's Lua API does not expose CPU registers (PC, CPSR, etc.). The original embedded script used `emu.getregister("pc")` which was an obsolete API. For full PC/mode tracing, use the Rust-based oracle in `crates/gbatopy-mgba` which interfaces with mGBA's internal state directly.

## Complete Verification Workflow

### One-Command Full Verification

```bash
# Generate golden screenshots (first time, or after mGBA changes)
python3 scripts/generate_goldens.py --frames 60

# Run full 3-level verification
python3 scripts/run_tests.py --level 3

For debugging a single ROM:

```bash
# 1. Transpile
cargo run -p gbatopy-cli -- pipeline --rom test_roms/roms/stripes.gba --output /tmp/stripes.py

# 2. Generate golden screenshot
GBATOPY_SCREENSHOT_PATH=/tmp/stripes_golden \
GBATOPY_TARGET_FRAME=60 \
./mgba/build/sdl/mgba -S scripts/screenshot/screenshot.lua test_roms/roms/stripes.gba

# 3. Generate transpiled screenshot
cd /tmp && python3 stripes.py --headless --frame=60 --screenshot /tmp/stripes_transpiled.png

# 4. Compare
python3 scripts/verify/compare_screenshots.py -s /tmp/stripes_golden.png /tmp/stripes_transpiled.png
```

**Result interpretation:**
- `PASS` — pixel difference < threshold (default 30%) and both images have content
- `FAIL` — pixel difference ≥ threshold
- `INCONCLUSIVE` — both images are black/empty (cannot verify correctness)

## Enforcement Checks

Deterministic shell scripts that enforce AGENTS.md rules without relying on AI compliance. Run before declaring a task done, or wire into a pre-commit/push hook.

### `check/no-skip.sh` — Zero-SKIP Policy (rule #26)

**Purpose:** Fail non-zero if `docs/reference/test-roms.md` summary line reports any SKIP ROMs.

```bash
bash scripts/check/no-skip.sh
```

Exit 0 = clean; exit 1 = SKIP count > 0. Parses the `Total ROMs: ...` summary line for the `⏰ SKIP` field.

### `check/no-debug-probes.sh` — No Stray Print Probes (rule #14)

**Purpose:** Fail if `crates/gbatopy-cli/src/pipeline_cmd.rs` or any file under `crates/gbatopy-cli/assets/gba_runtime/` contains a live `print(f"PC=` / `--pc-trace=` probe outside a comment. Commented-out probes are ignored.

```bash
bash scripts/check/no-debug-probes.sh
```

Exit 0 = clean; exit 1 = stray live probe found. Lists the offending file:line.

### `check/status-snapshot.sh` — Status Snapshot

**Purpose:** Print the current PASS/FAIL/SKIP/NEW counts from `docs/reference/test-roms.md`. Non-failing — informational.

```bash
bash scripts/check/status-snapshot.sh
```

Output format:
```
=== GBAtoPy Status Snapshot ===
PASS: 71
FAIL: 3
SKIP: 0
NEW:  2
Total: 76
==============================
```

### `check/doc-sync.sh` — Doc-Sync Enforcement (rule #23)

**Purpose:** Fail non-zero if files under `crates/` or `gba_runtime/` changed but `docs/reference/test-roms.md` did not. Ensures code fixes that change ROM pass/fail status are accompanied by doc updates.

**Usage:**
```bash
# Pass changed files as arguments
scripts/check/doc-sync.sh crates/gbatopy-cli/src/pipeline_cmd.rs crates/gbatopy-cli/assets/gba_runtime/ppu.py

# Or pipe from git diff
git diff --name-only HEAD | scripts/check/doc-sync.sh
```

Exit 0 = clean (docs updated or no code changed); exit 1 = code changed without doc update.

---

**Purpose:** Run all deterministic AGENTS.md enforcement checks in one command. Use before committing, before marking a task done, or at session start.

**Usage:**
```bash
# Run all checks (no changed files to check doc-sync)
scripts/check/preflight.sh

# Pass changed files for doc-sync check

```

Runs: `no-skip.sh`, `no-debug-probes.sh`, `doc-sync.sh` (if files provided), `status-snapshot.sh` (informational). Exits non-zero if any blocking check fails.
